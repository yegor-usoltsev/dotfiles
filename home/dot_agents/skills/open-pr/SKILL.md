# Open PR

The `origin` remote decides the host: `github.com` uses `gh`, `gitea.usoltsev.xyz` uses `tea`. Both CLIs are logged in.

Before filing, check whether a PR for this branch already exists (`gh pr view`, `tea pr ls --state open`) and update it instead of opening a second one. Review the diff against the base branch, usually `origin/main`, to make sure its contents match the goal.

## Title

PR titles usually become commit messages, so follow the repository's title convention; look at recently merged PRs and Git history. Prefer a concise title that says why the change matters:

> ❌ perf(server): negotiate permessage-deflate on the websocket
>
> ✅ perf(server): cut websocket frame size by 70%+ with gzipping

When the repository has a `.flint.json` and the work belongs to a Flint issue, prefix the title with the issue key in brackets, such as `[ENG-42] fix(cart): charge discounts once per line`. Take the key from the task, the branch name or the issue the user named.

## Description

Open with a simple explanation of the problem, based on the user's original request, then briefly explain the solution. Do not lead with an implementation inventory:

> ❌ Removed implicit workspace carry-over from every "new thread" entry point (cmd+n / cmd+shift+o, sidebar v1/v2 buttons, command palette). Deleted buildContextualThreadOptions and the v1 sidebar's seed-context machinery.
>
> ✅ My "new worktree" default was ignored when starting new threads on existing worktrees. Now your preferences always apply.

Add how you proved the change when it is not obvious from the diff: the failing-then-passing test, the command output or a screenshot. Describe the final implementation, without conversation history or abandoned approaches. Do not add model, harness or "generated by" lines.

Before submission, check the title, description, quotes and attachments for secrets and private details.

## File

Open a real PR rather than a draft so CI and review bots run. Pass a multi-line body through a file:

```sh
gh pr create --base main --title "$title" --body-file body.md
tea pr create --base main --title "$title" --description-file body.md
```

If `gh pr create` fails because the GraphQL rate limit is used up, open it through REST: `gh api repos/<owner>/<repo>/pulls -f title=... -f head=... -f base=... -F body=@body.md`.

In T3 Code, link the PR to the thread with `link_pull_request`.

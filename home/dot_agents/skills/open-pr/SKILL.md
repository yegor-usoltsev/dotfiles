# Open PR

Check the branch for an existing PR; update it instead of opening a duplicate. In T3 Code, prefer its pull request tools for lookup, creation and edits. Otherwise use `gh` for GitHub or `gt` for Gitea, according to `origin`. Review the diff against the intended base before filing.

## Title

PR titles usually become commit messages, so follow the repository's title convention; look at recently merged PRs and Git history. Prefer a concise title that says why the change matters:

> ❌ perf(server): negotiate permessage-deflate on the websocket
>
> ✅ perf(server): cut websocket frame size by 70%+ with gzipping

Use only figures you measured.

When the repository has a `.flint.json` and the work belongs to a Flint issue, prefix the title with the issue key in brackets, such as `[ENG-42] fix(cart): charge discounts once per line`. Take the key from the task, the branch name or the issue the user named. Then run `flint issue status "In Review" <KEY>`.

## Description

Open with a simple explanation of the problem, based on the user's original request, then briefly explain the solution. Do not lead with an implementation inventory:

> ❌ Removed implicit workspace carry-over from every "new thread" entry point (cmd+n / cmd+shift+o, sidebar v1/v2 buttons, command palette). Deleted buildContextualThreadOptions and the v1 sidebar's seed-context machinery.
>
> ✅ New threads on existing worktrees ignored the "new worktree" default. They now follow the user's preference.

Add how you proved the change when it is not obvious from the diff: the failing-then-passing test, the command output or a screenshot. Describe the final implementation, without conversation history or abandoned approaches. Do not add model, harness or "generated by" lines.

Before submission, check the title, description, quotes and attachments for secrets and private details.

## File

Open a real PR rather than a draft so CI and review bots run. Pass the body directly to the T3 tool. For CLI fallback use a temporary file of your own:

```sh
body=$(mktemp -t pr-body.XXXXXX.md)
gh pr create --base "$base" --title "$title" --body-file "$body"
gt pr create --base "$base" --title "$title" --body-file "$body"
```

## Media

Attach screenshots and recordings to the PR itself, not as gist links.

- GitHub: pass each file with `--attach` to `gh pr create`, `gh pr edit` or `gh pr comment` and reference it by local path, alone on its line (`![alt](./shot.webp)`, `![](./rec.mp4)`); gh uploads it and swaps in the URL. gh rewrites no other syntax, and GitHub drops `<video>` tags that point elsewhere.
- Gitea: open the PR, upload each file with `gt pr attachment upload <n> <file> --json url --jq .url`, embed the returned URLs as the global media rule says and run `gt pr edit <n> --body-file "$body"`.

If `gh pr create` fails because the GraphQL rate limit is used up, open it through REST: `gh api repos/<owner>/<repo>/pulls -f title=... -f head=... -f base=... -F body=@"$body"`.

T3 creation links the PR automatically; use `link_pull_request` after CLI creation.
